### 2. Domain Layer - JPA Entities

#### CurrencyPair Conversion

**Before (Record):**
```java
public record CurrencyPair(String base, String quote) {
    // Validation in compact constructor
}
```

**After (Embeddable JPA Component):**
- Converted to regular class with `@Embeddable`
- Added Lombok `@Data`, `@NoArgsConstructor`, `@AllArgsConstructor`
- Created `CurrencyPair.of()` factory method for validation
- JPA requires no-arg constructor and mutable fields

**Key Decision:** Sacrificed record immutability for JPA compatibility while maintaining validation through factory method.

#### PriceTick Conversion

**Key Changes:**
- Added `@Entity` and `@Table(name = "price_ticks")`
- Added `@Id` with `@GeneratedValue(strategy = GenerationType.IDENTITY)`
- Embedded [CurrencyPair](file:///home/pranay/anotherDrive/javaCodes/crypto-price-aggregator/src/main/java/com/cryptoArb/crypto_price_aggregator/domain/CurrencyPair.java#21-51) with `@Embedded`
- Used `@Enumerated(EnumType.STRING)` for Exchange enum
- Set `precision = 19, scale = 8` for BigDecimal columns
- Maintained record-like accessors ([pair()](file:///home/pranay/anotherDrive/javaCodes/crypto-price-aggregator/src/main/java/com/cryptoArb/crypto_price_aggregator/domain/PriceTick.java#99-105), [bid()](file:///home/pranay/anotherDrive/javaCodes/crypto-price-aggregator/src/main/java/com/cryptoArb/crypto_price_aggregator/domain/PriceTick.java#113-119), [ask()](file:///home/pranay/anotherDrive/javaCodes/crypto-price-aggregator/src/main/java/com/cryptoArb/crypto_price_aggregator/domain/PriceTick.java#120-126), etc.) for backward compatibility

**Database Schema Generated:**
```sql

    ask numeric(19,8) not null,
```

```
    ↓               ↓             ↓                  ↓

              saveAll()                          Min Ask
```

**Time Window Constant:**


This ensures aggregation uses fresh data while avoiding stale prices.

## Design Decisions & Trade-offs

### 1. Record → Class Conversion

**Trade-off:** Lost immutability benefits of records for JPA compatibility.

**Justification:** JPA requires:
- No-arg constructor (records don't have one)
- Mutable fields for proxy creation
- Option was to keep record with workarounds (Hibernate 6+), but chose clarity over complexity

**Mitigation:** Factory method `CurrencyPair.of()` maintains validation.

### 2. Time Window for Aggregation

**Decision:** Set 5-second window for "recent" ticks.

**Rationale:**
- Avoids aggregating stale data
- Balances freshness with data availability
- Constant `RECENT_TICKS_WINDOW_SECONDS` makes it configurable

**Alternative Considered:** Use all ticks ever saved → rejected (stale data problem)

### 3. Save-then-Query Pattern

**Flow:** Fetch → Save → Query → Aggregate

**Rationale:**
- Separates concerns (fetching vs. persistence vs. aggregation)
- Enables historical queries in future phases
- Database becomes source of truth

**Trade-off:** Slight performance overhead vs. in-memory aggregation.

### 4. Transaction Management

**Decision:** Add `@Transactional` to [PriceServiceImpl](file:///home/pranay/anotherDrive/javaCodes/crypto-price-aggregator/src/main/java/com/cryptoArb/crypto_price_aggregator/service/impl/PriceServiceImpl.java#48-145).

**Justification:**
- Ensures atomic save operations
- Spring manages EntityManager lifecycle
- Simplifies error handling

## Lessons Learned (TDD Journey)

### 1. RED-GREEN-REFACTOR Discipline

**RED Phase:** Repository test failed because [PriceTickRepository](file:///home/pranay/anotherDrive/javaCodes/crypto-price-aggregator/src/main/java/com/cryptoArb/crypto_price_aggregator/repository/PriceTickRepository.java#24-66) didn't exist.

**GREEN Phase:** Created minimal repository interface → tests passed.

**REFACTOR Phase:** Added custom query methods and verified with additional tests.

### 2. Backward Compatibility is Critical

When adding repository parameter to [PriceServiceImpl](file:///home/pranay/anotherDrive/javaCodes/crypto-price-aggregator/src/main/java/com/cryptoArb/crypto_price_aggregator/service/impl/PriceServiceImpl.java#48-145) constructor, **all existing tests broke**.

**Solution:** Updated test setUp to inject mock repository → minimized test changes.

### 3. Mock Repository Simulation

Initial stub returned empty list → tests failed.

**Fix:** Implemented "tracking" behavior:
- `saveAll()` appends to `savedTicks` list
- `findBy...()` filters from `savedTicks`

This simulates real persistence behavior in tests.
